# [Master CoT v3] WikiBrain: 지식 별지도 + 세계 지구본, 설치 없는 브라우저 완결형

## 0. 목표와 원칙
- 링크 하나로 누구나 쓴다. API 키, 가입, 설치, 서버 모두 없다.
- 창 두 개: `지식`(별지도), `세계`(three.js 지구본). 상단 탭으로 전환한다. 동시에 렌더링하지 않는다(8GB Mac).
- RAG와 Qwen 답변은 방문자 브라우저에서 돈다(WebGPU). LoRA 학습만 설치판(기존 브리지) 선택 기능으로 남긴다.
- 데이터는 공개 파일(덤프, RSS, CSV)만 받는다. 키가 필요한 소스(OpenDART, ACLED, FRED)는 쓰지 않는다.
- 팔란티어 고담은 문법만 참고한다(어두운 지도, 레이어, 시간 막대). 이름, 로고, 화면은 따라 하지 않는다.

## 1. 단계별 사고 순서 (각 단계: 생각 → 구현 → 검증 → 다음)

### Phase 1. 링크 시각화 (지식 창)
생각: 의미 공간은 "가까움"만 보여준다. 링크는 "뜻은 먼데 이어진" 연결을 보여줘야 재미있다.
- 1-A 링크 펼치기: 문서 클릭 → 나가는 링크마다 곡선(이차 베지어, 거리 비례 높이)과 흐르는 빛. 의미 거리 상위 링크를 강조.
- 1-B 위키레이스: 문서 두 개 선택 → 링크 그래프 양방향 BFS 최단 경로 → 경로 선 + 카메라 순차 비행.
- 데이터: 로컬은 `/api/links`, 사이트는 `data/links/*.bin` 조각. 양방향 BFS용 역링크 조각을 `5_site.py`에 추가.
- 검증: 경로 5쌍 손계산 대조, BFS 1초 이내, 링크 300개 이상 문서에서 60fps 유지.

### Phase 2. 문서 확장 (지식 창)
생각: 일반 지식(위키) + 경제·AI 전문 지식. 양보다 색으로 구분되는 소스가 중요하다.
- 소스: 한국어 위키낱말사전, 위키문헌, 위키책 덤프(기존 파이프라인 재사용), arXiv OAI 메타데이터 중 cs.AI, econ.*, q-fin.*.
- 임베딩: e5-base 그대로. 영어 초록은 `passage:` 그대로 넣고, 한국어 위키와 섞이는지 이웃 표본으로 확인.
- 배치: 기존 UMAP 허브 좌표를 고정하고 새 문서는 kNN 보간으로 넣는다(전체 재계산 금지, 기존 별 위치 보존).
- 화면: 소스별 별 색(`KIND_RGB` 확장), 범례.
- 검증: 소스별 문서 수, 새 문서 표본 20개의 이웃 적합도 눈검사, brain.bin 크기.

### Phase 3. 세계 지구본 최소 기능 (Phase 1과 동시 진행)
생각: 지구본은 "지금 어디서 무슨 일이 일어나는가"를 보여준다. 처음부터 레이어를 다 넣지 않는다.
- three.js 구 + Natural Earth 110m 국경선(정적 GeoJSON), 별지도와 같은 각인 셰이더 톤.
- 사건 점: 위도·경도 → 구면 좌표. 색 = 경제 / 정치 / 분쟁. 크기 = 점수.
- 시간 막대: 지난 24시간 ~ 7일.
- 검증: 서울·뉴욕·런던 좌표 위치 확인, 점 200개 60fps.

### Phase 4. 실시간 데이터 수집 (서버 없음)
생각: 서버를 두지 않으려면 수집을 GitHub Actions가 맡고 결과를 정적 JSON으로 배포한다.
- 15분마다 Actions: GDELT GKG 최신 파일(제목 `PAGE_TITLE`, 위치, 주제, 어조) + 구글 뉴스 RSS + arXiv RSS + DART 오늘의 공시 RSS.
- 주요 뉴스 거르기:
  1. 언론사 수 ≥ 5 (실데이터로 조정)
  2. 같은 주소, 같은 행위자 쌍, 같은 국가 묶기
  3. 점수 = log(기사 수) × |영향도| × 24시간 반감기
  4. 상위 200개, 나라당 최대 15개
- 한국 뉴스 위치: 위키 `{{좌표}}` 틀에서 뽑은 지명 → 좌표 사전으로 제목의 지명을 매칭.
- 하루 1회: World Bank, IMF 지표 CSV → 나라별 색칠 데이터.
- 결과: `site/data/live/*.json` 커밋 → Vercel 재배포.
- 보안: XML DOCTYPE/ENTITY 거부 유지, 외부 문자열은 화면에 텍스트로만 넣기, Actions에 비밀값 없음.
- 검증: GKG 제목 포함 비율, 15분당 원본 건수와 필터 후 건수, 주요 매체 헤드라인과 교차 확인.

### Phase 5. 두 창 연결
- 사건 → 관련 위키 문서: 기존 위성 별 엔티티 연결(제목 사전 + e5 + 허브 보정) 재사용.
- 문서 → "지도에서 보기": 좌표 있는 위키 문서는 지구본에도 표시.
- 지역 고르기: 지구본에서 원을 드래그 → 그 지역의 사건, 지표, 관련 위키 문서를 묶음으로 만든다. 별지도의 구로 고르기와 같은 형식.

### Phase 6. 브라우저 안 RAG + Qwen
- 질문 임베딩: transformers.js로 e5-base(양자화) 실행. 문서 임베딩은 미리 계산한 조각을 받는다.
- 본문: 문서당 앞 1200자를 조각 파일로 만든다. Vercel 한도를 넘으면 Hugging Face 데이터셋에 두고 필요한 조각만 받는다.
- 답변: WebLLM으로 Qwen2.5-1.5B-Instruct(q4) 실행. 첫 방문 약 1GB, 이후 캐시.
- WebGPU가 없으면(사파리, 휴대폰) 검색 결과만 보여주고 답변 대신 안내를 띄운다.
- LoRA: 사이트에서는 학습 데이터 묶음(JSONL)을 내려받기만 한다. 학습은 설치판 브리지에서 한다.
- 검증: 8GB Mac 크롬 기준 첫 토큰 시간, 메모리, 답변에 출처 문서가 인용되는지.

### Phase 7. 배포와 포트폴리오
- Vercel 정적 배포, CSP는 WebLLM 모델 주소(Hugging Face)와 GitHub Actions 산출물만 허용.
- 설치판: `curl … | sh` 한 줄(LoRA를 원하는 사람용), 토큰 링크 자동 열기.
- README: 데모 영상(위키레이스, 지구본 지역 선택 → 답변), 구조도, 데이터 라이선스(CC BY-SA, CC0).

## 2. 진행 순서
1. Phase 1 + Phase 3 동시
2. Phase 2 (재임베딩, 백그라운드)
3. Phase 4 → 5 → 6 → 7

## 3. 알려진 위험
- WebLLM 속도: 8GB Mac에서 느릴 수 있다. 0.5B 모델을 예비로 둔다.
- GKG 양이 많다: 필터는 Actions에서 끝내고, 브라우저에는 200건만 보낸다.
- 본문 용량: 전체 본문은 정적 배포 한도를 넘는다. 잘라서 조각으로 만든다.
- 영어 논문과 한국어 위키의 임베딩 정렬이 약할 수 있다. 이웃 표본으로 먼저 확인한다.
- 키 없는 피드(DART RSS, GDELT)가 바뀌거나 끊길 수 있다. 실패하면 직전 스냅샷을 유지한다.
