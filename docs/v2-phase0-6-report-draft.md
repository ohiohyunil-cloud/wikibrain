# WikiBrain v2 Phase 0~6 작업 보고 (초안, 2026-11-23)

설계서 v2(현실 보정판)의 Phase 0~6 코드를 모두 작성하고 8GB Mac에서 검증 항목 12개를 돌렸다. 8개는 기준을 넘었고 3개(M-2, M-8, M-12)는 못 미쳤다. 오프라인 동작(M-10)은 확인하지 못했다. Vercel 재배포와 프록시 배포는 하지 않았다.

## 시작 전 상태

임베딩(multilingual-e5-base, 768차원)은 770,097건 모두 끝나 있었다. 3D 배치 파일 brain.bin은 예전 MiniLM 임베딩 기준이었다. 위성 보정이 e5 코사인과 3D 거리를 함께 읽기 때문에, Phase 1에 앞서 brain.bin을 e5 기준으로 다시 만들었다. UMAP 3만 허브와 나머지 보간에 약 15분 걸렸다. 프로젝트 폴더를 옮기면서 가상환경이 사라져 Python 3.9.6으로 다시 만들었다. Python 3.13에서는 numba 0.59가 빌드되지 않는다.

## Phase별 결과

Phase 0. site/api/proxy.ts에 ArXiv, DART 프록시를 만들었다. https만 쓰고, type은 arxiv와 dart 두 가지만 받고, 검색어는 100자로 자르고, x-proxy-token 헤더가 없으면 401을 돌려준다. DART 회사명은 corpCode.xml을 미리 받아 JSON 맵(상장사만)으로 바꿔 두고 조회한다. 맵을 만드는 스크립트는 있지만 API 키가 없어서 아직 돌리지 않았다. 타입 검사만 통과했고 실제 호출은 해 보지 않았다.

Phase 1. 위성 배치 엔진(Adam 3회 재시작, 힌지 반발, 24시간 반감기)을 JS로 썼다. 지금 화면이 빌드 없이 돌아가서 TS 대신 JS를 골랐다. 테스트 중에 버그가 하나 나왔다. 반발 대상을 이완 전 위치 기준으로 고르다 보니 이완 뒤 다른 위성과 겹쳤다. 겹침 후처리를 전체 위성 대상으로 바꿔 해결했다.

보정 방식은 설계서와 다르게 갔다. 설계서는 무작위 문서 쌍의 코사인 중앙값(0.72)을 시그모이드 중심으로 쓴다. 그런데 실제 제약은 코사인 상위 9개 이웃(0.86~0.89)만 쓰기 때문에 목표거리가 전부 최솟값 4.6으로 몰렸고, 실제 뉴스 위성의 Stress가 3.89까지 올라갔다. 그래서 문서 300개의 상위 9개 이웃 코사인과 3D 거리로 다시 보정했다(c 0.876, 거리 12~376). Stress는 0.15로 내려갔지만 기준 0.10에는 못 미친다.

Phase 2. 들어오는 링크가 5개 미만인 별은 카메라에서 350 넘게 떨어지면 셰이더에서 크기와 밝기를 0으로 만든다. 버퍼를 다시 올리지 않는다.

Phase 3. Shift+드래그 올가미를 넣었다. CSS 픽셀 기준으로 판정하고, 77만 점 투영은 Vector3를 만들지 않고 typed array 루프로 계산한다. 바운딩 박스로 먼저 거르고 클립 w가 0 이하인 점은 뺀다. 결과는 링크 수 순으로 300개까지만 남긴다.

Phase 4. backend/mlx_bridge.py를 127.0.0.1:8001에 띄운다. embed, rag, chat, augment, status 다섯 개 엔드포인트가 있고 모두 X-Bridge-Token을 검사한다. RAG 원문은 덤프에서 본문을 다시 뽑아 SQLite(FTS5)에 넣었다. 770,097건에 문서당 앞 4,000자로 2.7GB이고, 추출에 약 20분 걸렸다.

Phase 5. n8n 1.123.100을 npx로 네이티브 실행했다. 웹훅에서 브리지 augment로 보내는 워크플로가 토큰을 실어 브리지까지 도달하는 것을 확인했다. n8n 1.x에는 설계서에 적힌 Basic Auth 설정이 없어서 첫 접속 때 소유자 계정을 만들어 보호해야 한다.

## 남은 일

M-8은 1.5B 모델이 긴 문맥을 읽는 시간이 원인이다. 올가미가 최대 300개를 고르는데 300개 × 2,000자를 그대로 넣으면 문맥이 60만 자가 된다. 질문과 가까운 문서 3~5개만 넣으면 2,000~6,000자 구간이 되지만, 그래도 첫 토큰 3초는 어렵다.

/api/embed의 77만 건 검색이 4.7초 걸린다. 설계서 예상은 0.5~1초다. float16을 청크마다 float32로 바꾸는 비용이 크다.

n8n은 브리지가 오류를 돌려줘도 빈 200으로 응답한다. HTTP 노드가 상태 코드를 그대로 넘기도록 바꿔야 한다.

브리지와 화면은 아직 연결하지 않았다. 지금 화면에서 되는 것은 올가미 선택까지다.

배포에는 Vercel 환경변수 PROXY_TOKEN, DART_API_KEY 등록과 회사코드 맵 생성이 먼저 필요하다.
